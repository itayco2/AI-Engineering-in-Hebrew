# Contributing

Two rules govern this repo. Everything else is detail.

**1. No logic in notebooks.** Every function lives in `aihe/`. A notebook cell imports, calls,
and shows. `tests/test_no_logic.py` fails the build on any `def` or `class` in a code cell.

**2. It must stay maintainable in about two hours a week.** If a change makes the repo more
expensive to keep alive than that, it is the wrong change, even if it is a good idea. Cut a
chapter before skipping a week.

## Why rule 1 is not negotiable

It buys four things at once, and nothing else buys them:

- **A fast test tier.** Pure functions in `aihe/` are unit-testable, so `make test` runs in under
  a minute with no model. Logic buried in cells cannot be tested at all.
- **Short notebooks.** Long cells are where RTL rendering falls apart. Import-call-show keeps
  every markdown block small enough to render correctly.
- **Real failure instead of silent wrongness.** A dependency bump breaks a test. The same bump
  inside a notebook cell produces a chapter that still "runs" and is quietly wrong.
- **Reviewable diffs.** A logic change shows up in a `.py` file, not in notebook JSON.

## The notebook contract: six files per chapter

`tests/test_contract.py` enforces this. Five chapters that each invent their own shape is the
failure mode it exists to prevent.

| File | Rule |
|---|---|
| `README.md` | Hebrew title, three lines of "what you'll build", the exact `make run-NN`, link to the rendered page. **Deliberately short**. GitHub renders Hebrew badly, so this is a signpost, not the chapter |
| `chapter.ipynb` | Hebrew markdown, English code. No `def`/`class`. First cell is imports. Last cell prints the chapter's headline number |
| `meta.yml` | `id, title_he, title_en, needs_llm, ram_gb, est_minutes, datasets[], models[], terms[]`. Drives the README table, the site nav, and which CI job runs the chapter |
| `data/` + `SOURCE.md` | Redistributable data only, licence named in `SOURCE.md` |
| `cassettes/` | Per-chapter, never global, so one chapter's churn cannot break another |
| `tests/test_chapter.py` | Asserts *this chapter's own claims*, on small inputs, without a model |

## Writing Hebrew that renders

RTL Markdown genuinely breaks on GitHub. These rules cost nothing and remove almost all of the
pain. `scripts/check_rtl.py` enforces the mechanical ones.

- **Never start a Hebrew paragraph with an English word or a code span.** No stylesheet can fix
  this inside GitHub's renderer, the whole paragraph flips to left-to-right. Only the writing
  rule fixes it. Open with a Hebrew word, every time.
- **Backtick every inline English fragment**: term, identifier, path, flag, URL. Then one CSS
  rule isolates all of them forever. Unbacktick'd English drags the line's direction.
- **Put measured numbers in tables or backticks**: never bare in Hebrew prose. `5.7% → 1.9%` in
  running Hebrew text puts the arrow and the percent signs in the wrong places.
- **Gloss a term once, then use one form.** First use may be `Hebrew (English)`; after that, the
  form in `TERMS.md` and nothing else.
- **Every RTL block needs `markdown="1"`**: `<div dir="rtl" lang="he" align="right" markdown="1">`.
  Without that attribute the `md_in_html` extension leaves the contents alone, and the whole
  block renders as literal text: visible hashes, pipes and link brackets. It looks like the
  site is broken rather than like a missing attribute, so `scripts/check_rtl.py` checks for it.
- **No em dashes, en dashes, curly quotes, ellipsis characters or decorative emoji.** Use a
  comma, a colon, or two sentences. These marks are the reason the docs read as machine-written,
  and `tests/test_terms.py` fails the build on any of them. The corpus in `chapters/*/data/` and
  the recordings in `cassettes/` are exempt: they are evidence, and evidence is reproduced
  exactly as it was found.
- Read `TERMS.md` before writing a sentence. It is the style spine, and the build checks it.

## Numbers

This repo inherits its number discipline from `driving-rl`, and it is the thing that makes the
teaching credible.

- **Prefer a number the notebook measures over a number you cite.** A chapter that reproduces a
  result on a small corpus beats ten that quote one. The reader believes what they just watched
  happen.
- **If you cite, verify at the primary source.** Not a blog summarising a paper, the paper.
- **Figures are generated by `aihe/viz.py`, never screenshotted.** A generated figure proves its
  own number and cannot go stale silently.
- When a chapter documents something that was broken, use the `PREFLIGHT.md` table shape from
  `driving-rl`: *what was wrong | the number that showed it | fix | the number after*.

## Running things

```bash
make setup      # venv + dependencies (uses uv when present, falls back to pip)
make gate       # under 60s; run this first when anything looks broken
make test       # pure functions, no model needed
make run-01     # execute one chapter end to end
make docs-serve # the RTL site, locally
```

`make gate` is also the troubleshooting tool. It checks that the package imports, the embedding
model downloads and embeds a sentence, every `meta.yml` parses, every dataset is reachable, and
every referenced cassette exists. When a stranger's install is broken, this is the first thing
to run and it usually names the problem.

## Models and cassettes

The shared client in `aihe/models.py` is one interface, `chat()` and `embed()`, with four
backends chosen by `AIHE_BACKEND`:

| Backend | For |
|---|---|
| `ollama` | the default for humans |
| `llamacpp` | the portable path: pip-only, works natively on Windows |
| `replay` | **the CI default.** Reads committed cassettes, makes no network calls |
| `fake` | canned strings, for unit tests |

Generated text is **not reproducible**, even at temperature 0 with a fixed seed, it drifts
between runs and differs across platforms. So no test ever asserts on generated text. Tests
assert on the deterministic parts: the retrieval, the metrics, the validators, the byte-exact
prefix check.

A cassette miss in `replay` mode fails loudly and names the command to fix it. To re-record:

```bash
make record     # rewrites cassettes from a real model; review the diff
```

Cassettes are content-hash-keyed and committed, with the model name and version pinned inside
the file, so bumping a model shows up as a visible diff rather than a mystery. `nbstripout` runs
in pre-commit so notebook output never enters a diff.

## Adding a chapter

Only after the previous one is deployed and posted. Five half-built chapters and a README
promising eight reads, to anyone evaluating this repo, as abandoned, which is worse than four
chapters and an honest roadmap.
